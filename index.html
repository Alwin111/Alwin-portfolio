WHAT IS VANGUARD

Vanguard is a self-contained, competition-grade hardware security badge built entirely by bi0s Hardware. It ships as a single device that participants receive at an event — and it is simultaneously a messenger, a game console, a LoRa radio, a BLE exchange tool, and a live embedded-security CTF target they can attack.

The firmware runs on an ESP32-S3 with a color TFT display, an addressable LED chain, a joystick + button cluster, a LoRa radio module, and buzzer audio — all powered from battery with zero infrastructure dependency beyond the badges themselves.

CORE CAPABILITIES
  • 4-Level On-Device CTF — hardware challenge arc spanning UART reconnaissance, RF/protocol reverse engineering, authenticated uplink scripting, and file-format forensics
  • LoRa Communications — shared physical/link layer powering Radio Chat, Ship Battle, and the challenge satellite link
  • BLE PeerDrop — badge-to-badge contact exchange over Bluetooth Low Energy (the same system as the standalone PeerDrop project)
  • Radio Chat + Morse Mode — handheld LoRa messenger with real CW send/receive capability
  • Ship Battle — badge-to-badge game running on the same LoRa link layer as Radio Chat
  • Games Suite — Tetris, Snake, Space Shooter, 2048 playable on-device
  • Logic Analyzer Exercises — Level 1 of the CTF arc is a hands-on UART sniffing exercise against real hardware
  • Competition Infrastructure — sequential unlock chain, persistent progress, and a companion satellite simulator
FIRMWARE ARCHITECTURE

Built on ESP-IDF with Arduino as a component, building entirely inside the official Espressif Docker image — no local toolchain required. A single AppState machine in main.cpp dispatches to one active screen at a time; always-on subsystem managers handle LEDs, audio, animation, and power independently of the active screen.

  • Screens implement enter()/frame() — clean separation between UI and hardware
  • NVS-backed persistence for identity, contacts, challenge progress, and preferences
  • Companion PC-side satellite simulator ships in the same codebase — both sides of the RF protocol in one repo
  • Docker-first build: ./tools/build.sh is the only command needed

PEERDROP

Secure, privacy-first, device-to-device BLE data exchange — no cloud, no accounts, no traceability. Two ESP32 boards communicating directly over Bluetooth Low Energy with identity and proximity validation baked in.

STATUS● Completed
TIMELINEDec 2025 – Jan 2026
HARDWARE2× ESP32 Dev Boards
PROTOCOLBluetooth Low Energy (BLE)
// HARDWARE — TWO ESP32 NODES RUNNING PEERDROP FIRMWARE
// SERIAL OUTPUT — BLE DISCOVERY, HANDSHAKE & DATA EXCHANGE
OVERVIEW

PeerDrop is a proximity-based BLE communication system that lets two ESP32 devices securely exchange contact information and data without any internet connection, cloud server, or persistent account. Think AirDrop but on bare-metal embedded hardware.

The serial output shows real device discovery — each board scanning for nearby BLE peers, validating their identity via badge ID and MAC address, then exchanging structured data (name, email, phone, organisation) with a single button press. The [✓] Exchange done confirmation confirms end-to-end delivery.

HOW IT WORKS
  • Each ESP32 acts as both a BLE advertiser and scanner simultaneously, broadcasting a unique badge ID while scanning for nearby peers
  • RSSI-based proximity validation ensures data exchange only happens when devices are physically close — preventing remote interception
  • On discovery, the user presses a single button to initiate exchange — data (name, contact, org) is transmitted over a custom BLE GATT profile
  • No persistent connection maintained after exchange — the link drops immediately, leaving no exploitable open channel
  • All data stored in ESP32 NVS (non-volatile storage) — survives power cycles, clearable on demand with RESET command

SMARTPOCKET TUTOR

A portable, voice-driven AI learning assistant built on ESP32. Ask it anything — it listens, thinks, and speaks back. Designed to give students access to intelligent tutoring without needing a smartphone or internet browser.

STATUS● Completed
TIMELINEMay 2025 – June 2025
HARDWAREESP32 + Microphone + Speaker + OLED
TYPEResearch Project
OVERVIEW

SmartPocket Tutor is an embedded AI assistant that runs on a low-cost ESP32 microcontroller. It takes voice input via microphone, processes it through an AI inference API, and delivers spoken answers through a small speaker — all displayed on a compact OLED screen.

The goal was to build a device that can serve as an intelligent study companion in areas with limited smartphone access, or for students who spend too much time context-switching on their phones.

HOW IT WORKS
  • Voice captured via I2S microphone, processed and streamed to AI inference API over Wi-Fi
  • Response received and converted to speech output through connected speaker module
  • OLED display shows query and response text in real-time for visual confirmation
  • Secure credential handling — API keys stored safely on-device, not hardcoded in firmware
  • Proposed offline mode using locally cached responses for commonly asked questions

BLE ASSET TRACKING SYSTEM

A hospital-grade real-time asset tracking system using ESP32 BLE nodes and a central Raspberry Pi server — designed to locate medical equipment instantly across large facilities.

STATUS◌ In Progress
USE CASEHospital Equipment Tracking
HARDWAREESP32 Nodes + Raspberry Pi Server
OVERVIEW

Medical equipment goes missing in hospitals constantly — this system solves that with a network of low-cost ESP32 BLE beacons and scanners feeding position data to a central Raspberry Pi dashboard.

ARCHITECTURE
  • ESP32 beacon nodes attached to assets continuously advertise unique BLE IDs
  • Scanner nodes at room entrances detect and report RSSI signal strength to the Pi server
  • Central server triangulates asset location and updates a live monitoring dashboard
  • Scalable mesh — add more nodes to cover larger floor plans without reconfiguration

META-LEARNING OPTIMIZATION FRAMEWORK

A research system that automatically selects the optimal optimization strategy for deploying pre-trained ML models on constrained hardware — removing the manual guesswork from edge AI deployment.

STATUS◌ In Progress
TYPEResearch Project
OVERVIEW

When deploying ML models to edge devices, engineers must manually choose between quantization, pruning, distillation and other optimization techniques — each with different accuracy/latency tradeoffs. This framework automates that decision.

HOW IT WORKS
  • Profiles the target hardware for compute, memory and latency constraints
  • Runs a meta-learning model trained on optimization experiment results to predict the best strategy
  • Benchmarks candidate optimizations and recommends the most efficient execution path
  • Reduces deployment time and improves inference efficiency without manual trial-and-error
