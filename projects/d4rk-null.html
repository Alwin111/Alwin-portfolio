D4RK NULL — ML-Based Adaptive PI Controller

An LSTM neural network that monitors controller behavior in real time and dynamically adjusts PI gain parameters to maintain optimal performance under changing conditions.

Python TensorFlow / Keras MATLAB Simulink NumPy Pandas Matplotlib

Overview

Traditional PI controllers use fixed gains (Kp, Ki) tuned for a particular operating condition. When disturbances occur — such as load changes or noise — the controller's performance can degrade, resulting in increased overshoot, slower settling, and reduced stability.

Our solution uses an LSTM-based adaptive controller that monitors error and disturbance history over time and generates correction factors for Kp and Ki in real time.

The underlying PI controller remains intact; the ML layer makes its gains self-adjusting to changing conditions.

Core Concept
Error + Disturbance History → LSTM → Kp Correction + Ki Correction

Gain Equations

Kpfinal = Kpbase × Kpcorr
Kifinal = Kibase × Kicorr

The LSTM learns the relationship between the controller's observed behavior and the gain adjustments required to improve the response. It does not replace the PI controller — it enhances it.

Technical Architecture

The complete pipeline from simulation to adaptive control:

Simulink Plant Simulation → Dataset Generation → Data Preprocessing → Time-Series Windowing → LSTM Model → Gain Correction → Safety Layer → Adaptive PI Controller → System Response

The ML model does not directly replace the PI controller. Instead, it provides controlled gain adjustments while the safety layer constrains the ML output. This architecture ensures the system degrades gracefully — if the ML model fails or produces unexpected outputs, the base PI controller continues to operate with its original gains.

📊 Simulink Plant Simulation

MATLAB Simulink model generates realistic plant behavior data under various operating conditions and disturbance scenarios.

🧠 LSTM Neural Network

Time-series model that processes error and disturbance history to predict optimal gain corrections for the current operating state.

🔒 Safety Layer

Constrains ML outputs to safe operating bounds, preventing abnormal corrections from destabilizing the control system.

⚙️ Adaptive PI Controller

Standard PI controller with dynamically adjusted gains, maintaining the reliability of conventional control.

Safety Layer

The safety architecture is a critical engineering feature that ensures the adaptive system remains stable even under unexpected conditions.

🔒 Gain Clamping

Hard limits on maximum and minimum gain values prevent the ML model from pushing gains beyond safe operating ranges.

📐 Safe Operating Bounds

Predefined constraints based on system identification ensure corrections stay within the controller's stable region.

🔄 Fallback Logic

If the ML model's confidence drops below threshold, the system automatically reverts to base PI gains.

🛡️ Anomaly Detection

Monitors ML output distribution to detect abnormal corrections before they reach the controller.

⚡ Base PI Fallback

The conventional PI controller remains fully operational underneath the adaptive layer — the ML enhances, never replaces.
